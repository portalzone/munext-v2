## Ground Rules — Read Before Every Session

### Git commits — no co-author tags
Never add "Co-authored-by: Anthropic" or any AI co-author tag to commit messages.
All commits are authored by Victor Muojeke only.
Commit messages must be clean, conventional, and professional:
  feat: add student profile endpoint
  fix: correct Pest test for auth module
  chore: update docker-compose with Redis
No AI attribution. No "generated by" notes. No Anthropic branding anywhere in the codebase.

### Cost discipline — use as few paid services as possible
Before suggesting any third-party service, API, or platform, ask:
  "Is there a free or self-hosted alternative that fits here?"
Preferred order:
  1. Built-in / native (e.g. Laravel queue over a paid queue service)
  2. Free tier (e.g. ChromaDB local over a paid vector DB)
  3. Open source self-hosted (e.g. Nginx over a paid gateway)
  4. Paid service — only if there is genuinely no good alternative
Never suggest services that add a monthly recurring cost without flagging the cost
and asking if I want to proceed. I am a student on a budget.

### Hostinger — use it where it fits
I have an active Hostinger Business plan already paid for.
Before suggesting DigitalOcean, AWS, Vercel, Railway, or any other hosting platform,
check whether Hostinger can serve the same purpose.
Hostinger Business supports: PHP/Laravel, MySQL, Node.js, SSL, custom domains,
SSH access, Git deployment, and cron jobs.
Use Hostinger for:
  - Laravel API hosting (if not requiring Kubernetes)
  - Static Next.js exports or simple SSR via Node.js
  - MySQL databases for development and staging
  - Domain and DNS management
Only move to DigitalOcean DOKS when Kubernetes or container orchestration
is specifically required (Project 4). For Projects 1, 2, and 3,
consider Hostinger first before reaching for cloud infrastructure.

### GitHub repo
The munext-v2 repo is PUBLIC on GitHub.
Never add secrets, .env files, API keys, or terraform.tfstate to any commit.
Always confirm .gitignore covers: .env, *.pem, terraform.tfstate, storage/logs/
before the first commit and after adding any new service.

## API conventions
- All routes prefixed: /api/v1/
- Auth: Laravel Sanctum (token-based)
- Responses: { data: ..., message: ..., status: ... }
- Errors: { error: ..., message: ..., status: ... }
- All endpoints must have a corresponding Pest test before being considered done

## Pest testing rules
- Every endpoint gets at least 3 tests: happy path, unauthenticated, invalid input
- Run tests with: php artisan test
- Tests live in Modules/{ModuleName}/Tests/
- Use Pest's fluent syntax — not PHPUnit style

## TypeScript rules
- Every API response must have a TypeScript interface in lib/types.ts
- No use of `any` type anywhere — if you do not know the type, ask
- All props must be typed — no untyped component props
