## What this project is
A data pipeline that reads job posting and student profile data from the MUNext MySQL
database, processes it with Apache Spark (running locally in Docker), and writes
aggregated analytics results back to dedicated analytics tables on the same MySQL
database. A Laravel API module on Hostinger serves those results. A live Recharts
dashboard in Next.js displays them.

This project builds DIRECTLY on top of the munext-v2 repo from Project 1.
Do not create a new repo — extend the existing one.

## Hostinger constraints — read this first

Hostinger Business is shared hosting. It does NOT support:
- Apache Spark (requires JVM — blocked on shared hosting)
- Redis (not available on any shared Hostinger plan)
- Laravel Horizon (requires Redis — not an option)
- Docker containers running server-side
- Long-running background processes (only cron-triggered one-shots)

What Hostinger Business DOES support (and what we use):
- PHP 8.3 at `/opt/alt/php83/usr/bin/php`
- MySQL (database: u144904804_munext, already set up)
- Cron jobs (used in Project 1 for queue workers)
- Node.js apps (Next.js frontend already deployed)
- SSH access, file manager, custom domains

### How we work around the constraints

| Original plan | Why it breaks on Hostinger | What we do instead |
|---|---|---|
| Spark runs on server | No JVM on shared hosting | Spark runs locally in Docker; writes to Hostinger MySQL via JDBC |
| Redis queue | No Redis on shared hosting | Laravel database queue driver (already set up in Project 1) |
| Laravel Horizon | Requires Redis | Skip Horizon; use database queue + cron + GitHub Actions |
| Automated Spark trigger | No persistent workers | GitHub Actions cron (free on public repo) runs the pipeline |

You still learn everything: PySpark, JDBC, data pipelines, queue concepts, Recharts.
The pipeline just runs on your machine (or GitHub's) instead of the server.

## Data flow — always keep this in mind
```
MySQL on Hostinger (live MUNext data: job_postings, applications, student_profiles)
  ↓ JDBC read
PySpark pipeline (runs in local Docker or GitHub Actions — NOT on Hostinger)
  ↓ transform + aggregate
  ↓ JDBC write
MySQL on Hostinger (analytics_* tables: pre-aggregated results)
  ↓ Eloquent model
Laravel Analytics API (api.basepan.com — running on Hostinger)
  ↓ JSON response
Next.js TanStack Query (munext.basepan.com)
  ↓ typed props
Recharts dashboard
```

## Spark pipeline rules
- Every pipeline must have a clear docstring: input table, transformation, output table
- Use MySQL JDBC driver (not PostgreSQL) — connector JAR must be in spark/jars/
- Always close the Spark session at the end: spark.stop()
- Test pipelines locally with a small --limit before running on full production data
- Log start time, end time, and row counts at each stage
- JDBC credentials come from environment variables — never hardcoded

## GitHub Actions rules
- Spark pipeline runs on schedule: `cron: '0 3 * * *'` (3am UTC daily)
- All DB credentials stored as GitHub Actions secrets (never in the YAML file)
- Workflow must: set up Java, install Python deps, run pipeline, report success/failure
- On failure: workflow fails visibly (no silent swallowing of errors)

## Laravel Analytics module rules
- Controllers read ONLY from analytics_* tables (never query live tables directly)
- Every endpoint must have a Pest test: happy path + empty data state
- No raw SQL — use Eloquent or the query builder
- Add analytics routes to the existing api.php route file under the Analytics module

## Recharts rules (TypeScript)
- Every chart component must receive typed props — no any
- All chart data fetched via TanStack Query — no raw fetch
- Every chart must have a loading skeleton and an error state
- Charts must be responsive (use ResponsiveContainer from Recharts)
- Recharts is already installed from Project 1 — do not reinstall
